AI Lead Qualification Agent

A multi-turn AI workflow that progressively qualifies leads, updates CRM state, and generates the next best qualification question.

This project automates the operational part of lead qualification: receiving a lead, checking existing CRM records, extracting qualification data with AI, routing the lead based on its current state, asking for missing information, updating the record, and requalifying as new answers arrive.

Business Context

Turn lead qualification from a one-time score into an ongoing workflow.

The project is designed around a practical problem: a lead may arrive with incomplete information. Instead of treating missing data as a dead end, the workflow keeps the qualification state, asks for the missing field, interprets the reply, updates the CRM, and recalculates the lead.

The problem

Lead records can contain only part of the information needed for qualification. The automation therefore needs to distinguish new and existing leads, preserve information already collected, and continue the conversation without losing the current qualification state.

  • Identify whether the lead already exists
  • Extract business problem, service interest, timeline, authority, and budget
  • Preserve previously captured information during requalification
  • Track which qualification question is waiting for an answer

The solution approach

The workflow uses AI for interpretation and question generation while deterministic automation handles routing, CRM updates, state transitions, and the movement of structured data between modules.

  • Webhook receives the latest lead interaction
  • CRM lookup separates existing and new leads
  • AI extracts structured qualification information
  • Routers decide what happens next
  • CRM state drives the next interaction

System Architecture

Separate AI interpretation from deterministic workflow control.

The design gives each component a specific responsibility: receive data, retrieve context, interpret language, route business logic, and persist the resulting state.

01 · Input

Webhook

Receives conversation ID, source, name, email, phone, company, and the latest message.

02 · CRM

Google Sheets

Searches and stores lead records, qualification fields, pending questions, and state.

03 · Intelligence

OpenRouter / AI

Extracts qualification data, interprets replies, scores leads, and generates follow-up questions.

04 · Control

Routers

Routes existing/new leads, qualification actions, answered fields, and requalification decisions.

05 · Structured Data

HTTP + JSON

Moves AI requests and responses through structured parsing before CRM updates.

Key design decisions

The architecture is intentionally designed around control, continuity, and incremental enrichment.

AI does not control everything

AI interprets language while automation controls routing, state, and CRM actions.

Qualification is progressive

A lead can provide information over several interactions instead of all at once.

CRM is the memory layer

Each interaction enriches the same lead record instead of creating disconnected conversations.

Missing information drives the next question

The workflow asks for what is still required rather than using generic follow-ups.

Requalification uses accumulated context

Every new answer improves the existing record instead of restarting the qualification process.

End Result

The lead record evolves with the conversation.

The workflow continuously turns new customer context into a more complete, structured, and actionable qualification record.
